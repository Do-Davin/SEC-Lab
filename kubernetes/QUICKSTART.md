## Step-by-Step Guide

### Part 1: Pods (20 minutes)

#### 1.1 Create your first pod

```bash
cd 01-pods

# Create a simple nginx pod
kubectl apply -f simple-pod.yaml

# Check if it's running
kubectl get pods

# View detailed information
kubectl describe pod nginx-pod
```

#### 1.2 Access the pod

```bash
# Port forward to access nginx
kubectl port-forward nginx-pod 8080:80

# Open browser to http://localhost:8080
# You should see the nginx welcome page

# Stop port-forward with Ctrl+C
```

#### 1.3 Interact with the pod

```bash
# View logs
kubectl logs nginx-pod

# Execute commands inside the pod
kubectl exec -it nginx-pod -- /bin/bash

# Inside the pod, run:
# ls /usr/share/nginx/html
# cat /usr/share/nginx/html/index.html
# exit
```

#### 1.4 Try multi-container pod

```bash
# Deploy multi-container pod
kubectl apply -f multi-container-pod.yaml

# Wait for it to be ready
kubectl get pods --watch
# Press Ctrl+C when ready

# Access the pod
kubectl port-forward multi-container-pod 8080:80

# Visit http://localhost:8080
# You'll see content generated by the debian container
```

#### 1.5 Clean up

```bash
kubectl delete -f simple-pod.yaml
kubectl delete -f multi-container-pod.yaml
```

### Part 2: Deployments (25 minutes)

#### 2.1 Create a deployment

```bash
cd ../02-deployments

# Create deployment with 3 replicas
kubectl apply -f simple-deployment.yaml

# Watch deployment creation
kubectl get deployments
kubectl get pods
```

#### 2.2 Scale the deployment

```bash
# Scale up to 5 replicas
kubectl scale deployment nginx-deployment --replicas=5

# Watch the scaling
kubectl get pods --watch
# Press Ctrl+C when all ready

# Verify
kubectl get deployments
```

#### 2.3 Update the deployment

```bash
# Update to a new nginx version
kubectl set image deployment/nginx-deployment nginx=nginx:1.22

# Watch the rolling update
kubectl rollout status deployment/nginx-deployment

# Check the new pods
kubectl get pods
kubectl describe deployment nginx-deployment | grep Image
```

#### 2.4 Rollback

```bash
# View rollout history
kubectl rollout history deployment/nginx-deployment

# Rollback to previous version
kubectl rollout undo deployment/nginx-deployment

# Verify rollback
kubectl rollout status deployment/nginx-deployment
```

#### 2.5 Test rolling update strategy

```bash
# Apply rolling update deployment
kubectl apply -f rolling-update-deployment.yaml

# Watch how pods update gradually
kubectl get pods -l app=rolling-app --watch
```

### Part 3: Services (25 minutes)

#### 3.1 Create a ClusterIP service

```bash
cd ../03-services

# Make sure deployment exists
kubectl apply -f ../02-deployments/simple-deployment.yaml

# Create ClusterIP service
kubectl apply -f clusterip-service.yaml

# View service
kubectl get services
kubectl describe service nginx-clusterip-service
```

#### 3.2 Test internal connectivity

```bash
# Create a test pod to access the service
kubectl run -it --rm debug --image=busybox --restart=Never -- /bin/sh

# Inside the pod, run:
# wget -qO- nginx-clusterip-service
# exit
```

#### 3.3 Create a NodePort service

```bash
# Create NodePort service
kubectl apply -f nodeport-service.yaml

# Get service details
kubectl get service nginx-nodeport-service

# If using Minikube:
minikube service nginx-nodeport-service

# If using Docker Desktop or other:
kubectl port-forward service/nginx-nodeport-service 8080:80
# Visit http://localhost:8080
```

#### 3.4 Create LoadBalancer service

```bash
# Create LoadBalancer service
kubectl apply -f loadbalancer-service.yaml

# Check status
kubectl get service nginx-loadbalancer-service

# If external IP is pending (local cluster):
kubectl port-forward service/nginx-loadbalancer-service 8080:80

# If external IP is assigned (cloud):
# Visit the external IP in browser
```

### Part 4: Load Balancing (30 minutes)

#### 4.1 Deploy load balancing demo

```bash
cd ../04-load-balancing

# Deploy the application
kubectl apply -f lb-deployment.yaml
kubectl apply -f lb-service.yaml

# Wait for pods to be ready
kubectl get pods -l app=lb-demo --watch
```

#### 4.2 Test load balancing manually

```bash
# Port forward to the service
kubectl port-forward service/loadbalancer-demo-service 8080:80

# In another terminal, send multiple requests
for i in {1..20}; do
  echo "Request $i:"
  curl localhost:8080
  echo ""
done

# You should see different pod hostnames
```

#### 4.3 Run automated test

```bash
# Make script executable
chmod +x test-load-balancing.sh

# Run the test
./test-load-balancing.sh

# Observe how requests are distributed across pods
```

#### 4.4 Scale and observe

```bash
# Scale to 10 replicas
kubectl scale deployment loadbalancer-demo --replicas=10

# Wait for new pods
kubectl get pods -l app=lb-demo

# Test again
for i in {1..30}; do curl localhost:8080; echo ""; done

# More pods = wider distribution
```

#### 4.5 Test sticky sessions

```bash
# Apply sticky session service
kubectl apply -f sticky-session-service.yaml

# Port forward to new service
kubectl port-forward service/sticky-session-service 8081:80

# In another terminal, test
for i in {1..20}; do curl localhost:8081; echo ""; done

# Should mostly see the same hostname (sticky sessions)
```

### Part 5: Complete Case Study (45 minutes)

#### 5.1 Deploy the e-commerce application

```bash
cd ../05-case-study

# Make scripts executable
chmod +x deploy-all.sh test-application.sh

# Deploy everything
./deploy-all.sh

# This will:
# - Create namespace
# - Deploy MongoDB database
# - Deploy backend API (4 replicas)
# - Deploy frontend (3 replicas)
# - Configure load balancing and auto-scaling
```

#### 5.2 Verify deployment

```bash
# Check all resources
kubectl get all -n ecommerce

# Check pod status
kubectl get pods -n ecommerce

# All pods should be in "Running" state
```

#### 5.3 Access the application

```bash
# Get the frontend service
kubectl get service frontend-service -n ecommerce

# If external IP is available:
# Visit http://<EXTERNAL-IP>

# If using local cluster:
kubectl port-forward -n ecommerce service/frontend-service 8080:80

# Visit http://localhost:8080
```

#### 5.4 Explore the application

1. Open the application in your browser
2. Click "Refresh Products" to see backend data
3. Click "Test Load Balancing" to see requests distributed
4. Check the server pod name changes with each request

#### 5.5 Test load balancing

```bash
# Run the test script
./test-application.sh

# This shows:
# - Frontend health
# - Backend API connectivity
# - Load distribution across backend pods
# - Resource usage
```

#### 5.6 Monitor the application

```bash
# Watch pods
kubectl get pods -n ecommerce --watch

# Check HPA status
kubectl get hpa -n ecommerce

# View backend logs
kubectl logs -n ecommerce -l app=backend --tail=50

# Follow logs in real-time
kubectl logs -n ecommerce -l app=backend -f
```

#### 5.7 Test scaling

```bash
# Manually scale backend
kubectl scale deployment backend-deployment -n ecommerce --replicas=8

# Watch new pods appear
kubectl get pods -n ecommerce

# Test load distribution again
./test-application.sh

# Scale back down
kubectl scale deployment backend-deployment -n ecommerce --replicas=4
```

#### 5.8 Explore components

```bash
# Check database
kubectl exec -it -n ecommerce deployment/mongodb-deployment -- mongosh --eval "db.adminCommand('ping')"

# Check backend service endpoints
kubectl get endpoints backend-service -n ecommerce

# Check frontend service endpoints
kubectl get endpoints frontend-service -n ecommerce

# View ConfigMaps
kubectl get configmap -n ecommerce
kubectl describe configmap app-config -n ecommerce

# View Secrets (values are base64 encoded)
kubectl get secrets -n ecommerce
kubectl describe secret app-secrets -n ecommerce
```

#### 5.9 Test resilience

```bash
# Delete a backend pod
kubectl delete pod -n ecommerce -l app=backend --force --grace-period=0 | head -1

# Watch it automatically recreate
kubectl get pods -n ecommerce --watch

# Application should remain accessible
# Visit http://localhost:8080 and test
```

#### 5.10 Clean up

```bash
# Delete entire application
kubectl delete namespace ecommerce

# Verify deletion
kubectl get namespaces
```

## 🎓 Key Takeaways

### Pods
- Pods are the smallest deployable units
- Can contain one or multiple containers
- Share network and storage
- Ephemeral by nature

### Deployments
- Manage desired state of pods
- Provide replica management
- Enable rolling updates and rollbacks
- Self-healing capabilities

### Services
- Provide stable network endpoints
- Enable service discovery
- Load balance across pods
- Different types for different use cases

### Load Balancing
- Automatic traffic distribution
- Health-based routing
- Session affinity options
- Scales with replicas

## 🔄 Common Workflows

### Deploy Application
```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl get all
```

### Update Application
```bash
kubectl set image deployment/app container=image:v2
kubectl rollout status deployment/app
```

### Scale Application
```bash
kubectl scale deployment/app --replicas=5
kubectl get pods
```

### Debug Application
```bash
kubectl get pods
kubectl describe pod <pod-name>
kubectl logs <pod-name>
kubectl exec -it <pod-name> -- /bin/bash
```

### Monitor Application
```bash
kubectl top pods
kubectl get events
kubectl logs -f deployment/app
```

## 🚨 Troubleshooting

### Pod not starting
```bash
kubectl describe pod <pod-name>
kubectl logs <pod-name>
kubectl get events
```

### Service not accessible
```bash
kubectl describe service <service-name>
kubectl get endpoints <service-name>
```

### Deployment stuck
```bash
kubectl rollout status deployment/<name>
kubectl describe deployment <name>
kubectl rollout undo deployment/<name>
```
